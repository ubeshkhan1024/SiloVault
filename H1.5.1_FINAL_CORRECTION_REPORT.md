## Summary of Changes

### 1. `backend/storage/resolver.py` - Stale Adapter Prevention

**Key Implementation:**
- Added retry loop with `max_retries = 3` in `resolve()` method
- When `current_gen != start_gen` (invalidation during construction):
  - Do NOT cache the constructed adapter
  - Do NOT return the constructed adapter
  - Continue retry loop to attempt resolution again
- After `max_retries` exhausted: raise `StorageUnavailableError` with clear message
- Preserves all existing behavior: account validation, authentication, disconnected-account handling, legacy fallback
- Thread-safe: uses existing `_cache_lock` for all generation checks

**Critical Logic:**
```python
for attempt in range(max_retries + 1):
    # ... existing validation and construction logic ...
    
    with self._cache_lock:
        if account_id in self._cache:
            return self._cache[account_id]
        current_gen = (self._account_generations.get(account_id, 0), self._global_generation)
        if current_gen == start_gen:
            self._cache[account_id] = adapter
            return adapter
        
        # Generation mismatch: do NOT cache, do NOT return, retry
        if attempt < max_retries:
            continue
        
        raise StorageUnavailableError("Failed to resolve adapter after retries")
```
