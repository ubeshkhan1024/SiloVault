## 1. Inspect resolver generation logic

### `AccountResolver.__init__` (Lines 69-83)
```python
def __init__(self, session_factory) -> None:
    self._session_factory = session_factory
    self._cache: dict[str, StorageOperations] = {}
    self._cache_lock = threading.Lock()
    self._account_generations: dict[str, int] = {}
    self._global_generation: int = 0
```
- Initializes per-account generation tracking (`_account_generations`) and a global generation counter (`_global_generation`)

### `resolve()` generation mechanism (Lines 143-199)
**Before construction (Line 143-146):**
```python
start_gen = (
    self._account_generations.get(account_id, 0),
    self._global_generation,
)
```
Captures the account generation and global generation prior to adapter creation.

**After construction, before caching (Lines 187-197):**
```python
with self._cache_lock:
    if account_id in self._cache:
        return self._cache[account_id]
    current_gen = (
        self._account_generations.get(account_id, 0),
        self._global_generation,
    )
    if current_gen == start_gen:
        self._cache[account_id] = adapter
```
- Re-reads the generation values while holding the cache lock
- If `current_gen == start_gen`, the freshly constructed adapter is cached
- If `current_gen != start_gen` (invalidation occurred during construction), the adapter is **NOT** cached

**Return behavior (Line 199):**
```python
return adapter
```
- The adapter is always returned to the caller (ensuring callers receive a valid result)
- The critical distinction: the stale adapter is NOT inserted into the cache when generations differ

### How the mechanism prevents stale caching
1. `start_gen` is captured **before** adapter construction begins
2. `invalidate_account()` increments `_account_generations[account_id]` and evicts from cache
3. After construction, `current_gen` is re-evaluated **under the cache lock**
4. If invalidation occurred during construction: `current_gen != start_gen` → adapter not cached
5. The next `resolve()` call for that account will construct a fresh adapter with current state
6. `invalidate_all()` increments `_global_generation`, invalidating all in-flight and cached adapters

### `invalidate_account()` (Lines 208-221)
```python
def invalidate_account(self, account_id: str) -> None:
    with self._cache_lock:
        self._account_generations[account_id] = (
            self._account_generations.get(account_id, 0) + 1
        )
        self._cache.pop(account_id, None)
```
- Thread-safe: acquires `_cache_lock`
- Increments per-account generation counter
- Evicts the cached adapter for that account

### `invalidate_all()` (Lines 223-231)
```python
def invalidate_all(self) -> None:
    with self._cache_lock:
        self._global_generation += 1
        self._cache.clear()
```
- Thread-safe: acquires `_cache_lock`
- Increments global generation counter
- Clears the entire adapter cache

## 2. Four new test implementations

### Same-account concurrency (Lines 335-389)
Uses `threading.Barrier(3)` synchronization (2 workers + mock_create):
- Both workers and the mock_create must pass through the barrier before any can proceed
- This guarantees both threads reach adapter construction simultaneously
- After barrier clearance, both callers receive the **same** adapter object (`results[0] is results[1]` via `is`)
- Verification: `assert resolver.resolve(local_account) is results[0]` (cached adapter returned on subsequent call)

### Different-account concurrency (Lines 393-453)
Uses `threading.Barrier(2)`:
- Two threads with different account IDs
- Barrier ensures deterministic concurrent execution
- Verification: `adapter1 is not adapter2` (separate instances), `adapter1.storage_root != adapter2.storage_root` (separate roots)

### Invalidation during construction (Lines 457-521)
Uses two `threading.Event` objects:
- `construction_started`: fired when worker enters construction phase
- `can_complete_construction`: fired to release paused construction
- Sequence: (1) worker starts, (2) test invalidates account while construction paused, (3) release construction
- Verification: `cached_adapter is None` (stale adapter not in cache), `fresh_adapter = resolver.resolve(local_account)` succeeds with new adapter

### Legacy fallback verification (Lines 525-578)
Tests three behaviors:
1. `resolver.resolve(None)` raises `ValueError` (NULL account ID rejected)
2. `resolver.resolve_legacy("LOCAL")` returns valid adapter (legacy path permitted)
3. `resolver.resolve(fake_id)` raises `ValueError` (non-NULL ID never falls back to registry)
- Registers LOCAL provider with proper `ProviderCapabilities` instance
- Cleans up registered provider in `finally` block
